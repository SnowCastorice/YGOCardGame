### 4. 卡图存储优化：双图库架构 + R2 对象存储
- **双图库架构**：
  - **原始图库**：存放各来源的所有卡图（twitter_photo、ygometa 等），不上传到 Git
  - **调用图库**：由 build 脚本从原始图库中按优先级选取每张卡每个稀有度的最优图，统一命名为 `{setNumber}_{rarity}.webp`
  - **游戏代码**：直接通过 `{localDir}/{setNumber}_{rarity}.webp` 索引，无需 image map 文件
  - **更新流程**：新图放入原始图库 → 跑一次 build 脚本 → 调用图库自动更新
  - **优势**：前端零选图逻辑、部署产物更小、选图逻辑可扩展（如质量检测）
- **R2 对象存储**：
  - 当前卡图已完全本地化，部署在 Cloudflare Pages
  - 后续计划迁移到 Cloudflare R2 对象存储
  - **触发时机**：活跃卡包超 10 个或本地图片体积影响部署时启动
